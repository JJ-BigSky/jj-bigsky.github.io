01 // What we deliver

Four ways we make it answer in time.Sustained thermal benchmarks, quantized runtimes, RT Linux, and fault-injected fallbacks.

E-01 // SILICON & THERMALS

Compute selection

Sized against a measured p99.9 latency and thermal budget inside a 45 °C sealed enclosure, not a datasheet TOPS peak.

Deliverables

  • Candidate modules benchmarked with your model under thermal load
  • Sustained-clock measurements vs. throttling thresholds
  • Enclosure thermal plan: conduction, airflow, and power budget
  • Hardware BOM recommendation with lifecycle and supply notes
E-02 // TENSORRT & QUANTIZATION

Model optimization

Quantization (INT8/FP8/FP4), layer fusion, distillation, and compiled runtimes—re-validated on your closed-loop task benchmark.

Deliverables

  • Compiled TensorRT / ONNX Runtime pipeline that builds from script
  • Distilled or quantized policy variants matched to your control rate
  • Full closed-loop evaluation suite run on every precision drop
  • Side-by-side latency vs. task-success trade-off table
E-03 // HARD REAL-TIME STACK

Real-time architecture

PREEMPT_RT kernel, CPU core isolation, IRQ pinning, and ROS 2 DDS/QoS profiles with a measured p99.9 jitter report.

Deliverables

  • RT-patched Linux image with isolated servo and inference cores
  • Pinned camera/NIC interrupts and locked memory (mlockall)
  • Documented ROS 2 DDS and QoS configuration tuned to the loop
  • Measured 24-hour p99.9 latency and jitter report under load
E-04 // SAFE RECOVERY

Degradation design

Deterministic controller behavior when a policy frame is late or uncertain, proven under fault injection.

Deliverables

  • Deterministic late-frame state machine (hold, re-approach, handoff)
  • Out-of-distribution and confidence thresholds tested on hardware
  • Fault-injection test pass (dropped camera frames, GPU stall, net loss)
  • Safety-file evidence package for your compliance review

02 // Control-rate architecture

What fits inside each control period.Average latency is a marketing number. Robots crash on the p99.9 tail.

Control ratePeriodWhat fits on the robot
1000 Hz1 msJoint servo and torque loop. Classical control only—nothing learned runs here.
100 Hz10 msReactive force/impedance control and small distilled MLP/diffusion heads.
30 Hz33 msCompiled visuomotor policies and standard manipulation control loops.
10 Hz100 msMulti-camera 3D perception, VLA action chunking, and re-grasp planning.
< 1 Hz> 1 sHigh-level task planning and language reasoning (safe to run off-robot).

A quantized model is a different policy. Dropping precision from FP16 to INT8 or FP4 buys 2×–4× speedups, but alters decision boundaries on edge-case grasps. Every quantized build must pass the full closed-loop evaluation harness before touching the line.

Design rule: benchmark p99.9 latency under sustained 45 °C enclosure load, and verify the late-frame fallback under fault injection.
